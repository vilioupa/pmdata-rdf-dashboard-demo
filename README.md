# Σημασιολογική Ανάλυση Δεδομένων Wearables (PMData) — Εκτελέσιμο Δείγμα

Το παρόν αποτελεί ένα μικρό, άμεσα εκτελέσιμο δείγμα του συστήματος της πτυχιακής,
το οποίο μετατρέπει δεδομένα από φορετές συσκευές (dataset PMData) σε σημασιολογικές
τριπλέτες RDF με τις οντολογίες SOSA/SSN, τις φορτώνει σε βάση γράφων GraphDB και τις
αναλύει μέσα από ένα διαδραστικό dashboard (Streamlit).

## Σχετικά με αυτό το δείγμα

Το πλήρες σύστημα της εργασίας επεξεργάζεται 12 χρήστες (P01–P12) και παράγει περίπου
100 εκατομμύρια τριπλέτες (~15 GB), όγκος που καθιστά δύσκολη τη γρήγορη εγκατάσταση και
εκτέλεση από τρίτους. Για τον λόγο αυτό, εδώ παρέχεται ένα μειωμένο υποσύνολο ώστε να
μπορεί κανείς να κατεβάσει και να τρέξει ολόκληρο το σύστημα σε λίγα λεπτά.

Το κείμενο και τα αποτελέσματα της πτυχιακής βασίζονται στο πλήρες dataset. Το παρόν
δείγμα προορίζεται αποκλειστικά για εύκολη εκτέλεση και επίδειξη του συστήματος.

Οι διαφορές του δείγματος από το πλήρες σύστημα είναι οι εξής:

- Περιλαμβάνει 3 χρήστες (P02, P03, P04) αντί για 12.
  Οι χρήστες αυτοί περιλαμβάνονται στις αναλύσεις και τα στιγμιότυπα που παρουσιάζονται
  στο κείμενο της εργασίας.
- Τα δεδομένα καρδιακών παλμών έχουν αραιωθεί σε περίπου μία μέτρηση ανά λεπτό, αντί για
  κάθε λίγα δευτερόλεπτα.
- Ο συνολικός όγκος είναι περίπου 7 εκατομμύρια τριπλέτες αντί για ~100 εκατομμύρια.
- Οι υπόλοιποι τύποι δεδομένων (ύπνος, ευεξία, δραστηριότητα, βήματα, πλαίσιο) περιλαμβάνονται
  πλήρεις.
- Το βήμα τεμαχισμού των μεγάλων αρχείων (`split_files.py` στο πλήρες σύστημα) δεν
  χρησιμοποιείται εδώ, καθώς τα αρχεία του δείγματος είναι ήδη μικρά και φορτώνονται απευθείας.
- Για να μπορεί το δείγμα να εκτελείται ανεξάρτητα και ταυτόχρονα με το πλήρες σύστημα,
  ενδέχεται να υπάρχουν μικρές διαφορές οργάνωσης και ρυθμίσεων σε σχέση με την υλοποίηση
  που περιγράφεται στο κείμενο της εργασίας, για παράδειγμα, η θέση ορισμένων αρχείων
  (όπως το `app.py`) και οι θύρες δικτύου (7201 και 8502 αντί για 7200 και 8501).

Σημείωση: επειδή το δείγμα περιλαμβάνει λιγότερα δεδομένα, ορισμένοι πίνακες του dashboard
ενδέχεται να εμφανίζονται με κενές σειρές. Τα σταθερά ύψη των πινάκων είναι ρυθμισμένα για
τον όγκο του πλήρους dataset και δεν επηρεάζουν τη λειτουργία.

## Προαπαιτούμενα

- Docker Desktop (περιλαμβάνει το Docker Compose). Σε Windows απαιτείται ενεργό το WSL2·
  δείτε την ενότητα «Αντιμετώπιση προβλημάτων» αν το Docker δεν ξεκινά.
- Python 3.11 ή νεότερη (δοκιμασμένο με 3.12), για την παραγωγή των RDF και την προαιρετική
  επικύρωση.

## Λήψη του project

Μέσω Git:

```
git clone https://github.com/vilioupa/pmdata-rdf-dashboard-demo.git
cd pmdata-rdf-dashboard-demo
```

Εναλλακτικά, κατεβάστε το ως ZIP από το repository και αποσυμπιέστε το.

## Δομή του project

```
pmdata-rdf-dashboard-demo/
  data/                    Δεδομένα-δείγμα (P02, P03, P04)
  scripts/
    build_demo_data.py     Script δημιουργίας του δείγματος (μόνο για αναφορά)
    ...                    (Οι parsers SOSA/SSN και η επικύρωση SHACL)
  app.py                   Το dashboard (Streamlit)
  main.py                  Παράγει τους γράφους για όλους τους χρήστες
  docker-compose.demo.yml  Απομονωμένο περιβάλλον (GraphDB + dashboard)
  Dockerfile               Περιβάλλον εκτέλεσης του dashboard
  requirements.txt         Εξαρτήσεις Python
  README.md
```
*Σημείωση: Το αρχείο `build_demo_data.py` περιλαμβάνεται αποκλειστικά για λόγους διαφάνειας 
(proof of work), ώστε να φαίνεται η μεθοδολογία υποδειγματοληψίας (downsampling) που 
εφαρμόστηκε στο αρχικό σύνολο δεδομένων. Δεν χρειάζεται να εκτελεστεί, καθώς ο φάκελος 
`data/` περιέχει ήδη τα έτοιμα, μειωμένα αρχεία.*

Ο φάκελος `rdf_output/` δεν περιλαμβάνεται. Παράγεται τοπικά από το βήμα 1 παρακάτω.

## Οδηγίες εκτέλεσης

Οι εντολές παρακάτω δίνονται για Windows (PowerShell). Οι αντίστοιχες για macOS/Linux
αναφέρονται όπου χρειάζεται.

### 1. Παραγωγή των γράφων RDF

Δημιουργήστε ένα εικονικό περιβάλλον Python και τρέξτε την main, καλώντας απευθείας
το Python του περιβάλλοντος (χωρίς `activate`, ώστε να αποφευχθούν περιορισμοί εκτέλεσης
scripts στο PowerShell). Από τη ρίζα του project:

```
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe main.py
```

Σε macOS/Linux, οι δύο τελευταίες εντολές γίνονται:

```
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python main.py
```

Η παραγωγή διαρκεί περίπου 4–5 λεπτά. Με την ολοκλήρωση, ο φάκελος `rdf_output/` περιέχει
τους γράφους των τριών χρηστών σε μορφή Turtle (.ttl) και N-Triples (.nt).

### 2. Εκκίνηση των υπηρεσιών

Με ανοιχτό το Docker Desktop, από τη ρίζα του project:

```
docker compose -f docker-compose.demo.yml up -d --build
```

Η πρώτη εκτέλεση κατεβάζει την εικόνα της GraphDB και χτίζει το dashboard, οπότε διαρκεί
λίγα λεπτά. Μόλις ξεκινήσουν οι υπηρεσίες, θα είναι διαθέσιμες:

- GraphDB Workbench: http://localhost:7201
- Dashboard: http://localhost:8502

Δώστε στη GraphDB περίπου 30–40 δευτερόλεπτα να αρχικοποιηθεί προτού την ανοίξετε. Αν τα
Windows εμφανίσουν ερώτημα του τείχους προστασίας για το Docker, επιλέξτε «Να επιτρέπεται η
πρόσβαση».

### 3. Δημιουργία του αποθετηρίου

Στο GraphDB Workbench (http://localhost:7201), από το μενού Setup επιλέξτε Repositories και
στη συνέχεια Create new repository. Επιλέξτε GraphDB repository, δώστε ως Repository ID την
τιμή `thesis` και δημιουργήστε το διατηρώντας τις προεπιλεγμένες ρυθμίσεις. Έπειτα ορίστε το
`thesis` ως ενεργό αποθετήριο.

### 4. Μεταφορά των γράφων στη βάση

Αντιγράψτε τα παραγόμενα αρχεία μέσα στον φάκελο εισαγωγής του container της GraphDB. Από τη
ρίζα του project:

```
docker cp rdf_output/. graphdb_demo:/root/graphdb-import/
```

### 5. Φόρτωση των δεδομένων

Στο Workbench, από το μενού Import επιλέξτε RDF και έπειτα την καρτέλα Server files. Εκεί
εμφανίζονται οι φάκελοι P02, P03 και P04 με τα αρχεία τους. Επιλέξτε τα όλα και ξεκινήστε τη
φόρτωση, διατηρώντας τις προεπιλεγμένες ρυθμίσεις εισαγωγής. Η φόρτωση διαρκεί λίγα λεπτά,
καθώς τα αρχεία δραστηριότητας και καρδιακών παλμών είναι τα μεγαλύτερα.

### 6. Χρήση του dashboard

Ανοίξτε το http://localhost:8502. Από το πλαϊνό μενού επιλέγετε χρήστη (P02, P03 ή P04) και
σελίδα ανάλυσης. Οι αναλύσεις εκτελούνται σε πραγματικό χρόνο πάνω στα δεδομένα του γράφου.

## Επαλήθευση (προαιρετικό)

Για να επιβεβαιώσετε τον συνολικό αριθμό τριπλετών, στο Workbench, στη σελίδα SPARQL,
εκτελέστε το εξής ερώτημα (αναμένονται περίπου 7 εκατομμύρια):

```sparql
SELECT (COUNT(*) AS ?triples) WHERE { ?s ?p ?o }
```

Για σημασιολογική επικύρωση του γράφου με SHACL:

```
.venv\Scripts\python.exe scripts\validate_shapes.py
```

## Τερματισμός και επανεκκίνηση

Για προσωρινό σταμάτημα των υπηρεσιών, χωρίς απώλεια δεδομένων:

```
docker compose -f docker-compose.demo.yml stop
```

Για επανεκκίνηση:

```
docker compose -f docker-compose.demo.yml start
```

Η εντολή `docker compose -f docker-compose.demo.yml down -v` διαγράφει το αποθετήριο του
δείγματος και θα απαιτούσε επανάληψη της φόρτωσης. Χρησιμοποιήστε την μόνο για καθαρό
ξεκίνημα.

## Αντιμετώπιση προβλημάτων

Το Docker Desktop δεν ξεκινά και εμφανίζει σφάλμα εικονικοποίησης ή «Engine stopped»
(σε Windows): ανοίξτε τη Γραμμή εντολών ως διαχειριστής, εκτελέστε `wsl --install`, εγκρίνετε
τα σχετικά παράθυρα και κάντε επανεκκίνηση του υπολογιστή. Έπειτα ανοίξτε ξανά το Docker
Desktop και περιμένετε να εμφανιστεί η ένδειξη «Engine running».

Η εντολή `.venv\Scripts\activate` εμφανίζει σφάλμα «running scripts is disabled»: αυτό είναι
περιορισμός του PowerShell. Οι οδηγίες παραπάνω τον παρακάμπτουν, καλώντας απευθείας το
`.venv\Scripts\python.exe`, οπότε δεν χρειάζεται καμία αλλαγή ρυθμίσεων.

Το http://localhost:7201 δεν φορτώνει αμέσως μετά την εκκίνηση: η GraphDB χρειάζεται λίγα
δευτερόλεπτα να αρχικοποιηθεί την πρώτη φορά. Περιμένετε και ανανεώστε τη σελίδα.
